# EdgeTier 0.2.1

Patch release for host/DDNS observation, client configuration and relay lifecycle fixes. EasyTier compatibility targets version 2.6.4.

## Changes

- Host and profile reads preserve healthy hosts when another host is unavailable. Failed hosts show explicit unavailable state; cached data remains visibly stale and direct export is blocked until recovery.
- Collector 1.0.1 fits the complete report into 64 KiB while retaining DDNS, service status, node information and command acknowledgement. Reduced topology carries an explicit partial-data marker and an omitted-peer count. Invalid control/DEL or oversized Unicode names cannot reject unrelated observations.
- Service pages distinguish active state, substate, raw unit-file state and persistent enablement. Static or runtime-enabled units are no longer presented as permanently enabled.
- DDNS refresh keeps the single fixed systemd command, durable execution/acknowledgement journal and ten-minute request lifetime. Collector timing now covers its permitted execution path; the heartbeat timer declares one-second scheduling accuracy. Dotted host IDs match the Worker contract.
- Client export uses profile endpoints and separates room ID from network name. It validates current direct-peer confirmation, IPv6 requirements, static IPv4 syntax and temporary WSS token identity/expiry at every export gesture. Late responses from a previous room/profile cannot replace the selected identity.
- Relay repairs bind each object to one room, retain an accepted surviving peer transport after another closes, merge owner-versioned route/connection rows, and bound queued frames, outstanding route requests and fragment retention. Malformed room encodings return a controlled error before storage access.
- The implicit `EASYTIER_PUBLIC_PEER_TCP` return path belongs only to the resolved default room. Explicit per-room peer maps preserve their configured scope, preventing another room from taking the gateway return path.

## Upgrade and recovery

The production release adapter exports the repaired modern RelayRoom while retaining the existing Directory, ConfigServerProbe, login and official EasyTier Web bridge. Existing administrator credentials, mesh identity, namespace data, bindings and collector configuration are preserved. This patch introduces no new Durable Object lifecycle migration on the existing 0.2.0 deployment. The active Cloudflare version is `b627f4e1-f07d-40bf-9d05-dd6e9feb7dd0`; all 19 existing bindings are unchanged. Collector configuration bytes, file mode and modification time are unchanged.

Deploy the modern Worker before collector 1.0.1 and its updated units: previous reports remain accepted, while the older receiver rejects the new optional telemetry fields. Forward recovery must retain all required classes and namespace data. Production deployment and real mesh/DDNS/browser acceptance are recorded in the release task's validation report.

## Validation and limits

Verified release checks:

- Vitest: 185 tests across 27 files; assembled-entry tests: 11; Python tests: 38. Typecheck, protocol drift check and build/dry-run passed.
- A native IPv6 client using real TCP/UDP peers returned HTTP 200 for all three HTTP acceptance probes.
- A WSS-only client connected to Cloudflare over IPv4 returned HTTP 200 for all three probes on two checks after the default-room return-path fix. Gateway-to-Worker TCP connections settled at one.
- On 2026-10-05 (UTC), the DDNS request was created at `13:51:14.481Z`, completed at `13:51:49Z`, and its acknowledgement report was received at `13:51:52.986Z`.

Temporary clients, their configuration and logs were cleaned up after testing. The final check after cleanup confirmed that easytier-core-home, easytier-web, edgetier-home-cloudflared and the DDNS/host timers remained active. The official EasyTier Web internal sessions API returned HTTP 200 with two sessions.

The native clients ran on OneCloud. These results establish the tested joins and HTTP paths; independent WAN UDP was not tested.

The product retains one administrator identity, the existing fixed official-Web UID 2 mapping, up to 16 configured hosts, one selected EasyTier instance per collector and four monitored service units. Direct peers require a fresh DNS-only AAAA/provider confirmation and IPv6 underlay; multi-address/interface selection remains conservative. Saved five-minute WSS join credentials require renewal before unattended reconnect. Existing mixed historical observer data is preserved rather than inferred into separate meshes. This patch does not add an account/role or arbitrary service-management system.
