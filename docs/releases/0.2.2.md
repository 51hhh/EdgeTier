# EdgeTier 0.2.2 — DDNS resilience, config export and meaningful history

Date: 2026-10-08 (Asia/Shanghai). Published to production; browser and host acceptance completed.

## Changes

- The OneCloud DDNS writer verifies its bound IPv6 source against independent HTTPS endpoints, with bounded fallback and candidate concurrency. Every accepted response must match the selected IPv6 exactly. All-probe failures and ambiguous verified addresses have different error codes. Failed verification never overwrites DNS.
- Client export uses the configured hostname and port even when DDNS or host observations are stale, unavailable or failed. Verification is shown separately, with an advisory comment in unverified exports. Invalid endpoints, mismatched identity, missing secrets, invalid static addresses and expired WSS credentials still fail validation.
- Consecutive identical DDNS observations are collapsed into state segments, showing first/latest observation and count. Keep up to 64 transitions, plus a separate ledger of the latest 16 successfully confirmed addresses. Repeated failures cannot evict the address ledger.
- Existing raw history is compacted in place. Where the latest report still retains a successful confirmation that fell out of the old 32-row window, an explicitly labelled checkpoint is recovered. Missing older addresses are not invented. Receipt time and report sequence are not refreshed by migration.
- Collector 1.0.2 reports DDNS and reporting jobs alongside their timers. Last execution result and exit code are shown independently of active/enabled state. An active timer does not imply a successful DDNS run.
- Correct misleading “verified direct peer” and status-unavailable copy. Keep network secrets in the browser; preserve production authentication and legacy official-Web/config-server routing.

## Verification

- TypeScript typecheck and protocol drift check.
- Vitest: 192 tests across 28 files, including long repeated failures, multiple IPs, flapping failures, migration/restart, and export during DDNS outage.
- Production entry assembly: 11 checks, preserving legacy authentication/bridge and the existing relay namespaces.
- Python: 42 checks for the writer, collector and rollout. Source verification rejects mismatched IPv6, IPv4, malformed responses and timeouts; job results do not inherit timer results.
- OneCloud: `api6.ipify.org` returned the exact bound source while the previous Cloudflare IPv6 check failed. Actual rollout, refresh acknowledgement, history and file-download checks are recorded separately.

## Review findings and remaining scope

- Official Web managed sessions and native EasyTier peers are different inventories. A successful bridge response with zero sessions is not proof that the three observed mesh nodes are offline. Check configuration-server registration and account ownership before adding management controls.
- The deployment retains one administrator, fixed official-Web user mapping and a bounded host profile list. Independent users/roles and arbitrary instance/service management are not implemented by this patch.
- Five-minute WSS credentials remain temporary. Export does not silently extend their lifetime or guarantee unattended reconnects.
- IPv6 direct port reachability remains a separate check. A valid TOML file or a successful DNS check does not establish UDP/WSS connectivity.
- OneCloud still negotiates 100 Mbps. Frontend chunk-size warnings and local-vs-production admin credential drift remain separate maintenance items.
- Historical counts cover retained observations/confirmations; this release cannot recover records already lost before migration.
