# EdgeTier 0.2.3 — isolated previews and DDNS state consistency

Date: 2026-10-08 (Asia/Shanghai). Published and accepted in production.

## Changes

- Test peers, events and traffic now live in a separate in-memory preview. They are displayed in a labelled preview card and excluded from live peers, WebSocket counts, traffic, topology and directory summaries. Clearing the preview preserves real sessions, route observations, history, samples and stored control state. Repeated preview generation replaces the previous preview.
- A DDNS command completed before its execution deadline can reconcile an expired status when its acknowledgement arrives later. The command ID and completion time are checked; old acknowledgements cannot overwrite a newer command, and the expiry error is removed after reconciliation.
- The DDNS writer binds retained confirmations to a non-secret fingerprint of the zone, record ID and hostname. Changes of identity cannot relabel an old success. A legacy status lacking the fingerprint is not reused as a confirmation after an error; existing cloud history remains retained.
- The collector checks that the writer-selected IPv6 is still present and eligible on eth0, including when multiple stable addresses coexist. An absent, temporary, tentative, deprecated or expired address does not pass this check. This membership check does not assert public port reachability.
- A separate A record may coexist with the configured AAAA. The writer reads and updates the configured record ID, queries AAAA separately and leaves A untouched. Additional AAAA records still produce an ambiguity error to prevent stale addresses being published alongside the managed address. Conversion of the configured A to AAAA remains supported when no AAAA exists.
- Collector version: 1.0.3. Worker version: 0.2.3. No Durable Object migration, profile replacement or credential change is required.
